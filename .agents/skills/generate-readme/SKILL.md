# Generate README（ソースコード説明の追記）

## 目的

ユーザーが指定したディレクトリ配下のソースコードを解析し、同じディレクトリ内にある `README.md` の `#### ソースコードの説明` セクションにコードの解説を生成・追記する。

---

## トリガーの例

- 「`post_2026/0806` のREADMEにソースコード説明を追記して」
- 「指定したディレクトリのコードを解析してREADME.mdを更新して」
- 「READMEのコード解説を作成して」

---

## 対象範囲

- 指定されたディレクトリ直下のソースコードおよび設定ファイル（`*.py`, `pyproject.toml` など）
- 必要に応じて参照しているサブディレクトリ内のモジュール（`modules/*.py` など）
- 各ファイルの import / dependency（依存パッケージ、連携関係）

---

## 重要なルール

1. **既存コンテンツの保護**:
   - `### 記事` のURLやタイトルなど、`#### ソースコードの説明` 以外の既存セクションは一切改変・削除しない。
2. **見出し位置への追記**:
   - すでに作成されている `README.md` の `#### ソースコードの説明` の直下に解説内容を記載する。
   - もし `#### ソースコードの説明` 見出しが存在しない場合は、記事情報などの下に適切に見出しを設けて追記する。
3. **記述フォーマットの統一**:
   - 最初にそのディレクトリの目的・概要を1〜2文で記載する。
   - ファイルごとに `- `filename`` 形式で箇条書きにし、そのインデント下に主要な処理内容、利用クラス/関数、依存関係を具体的に説明する。
   - 必要に応じて全体のまとめ（動作概要や目的）を簡潔に補足する。
   - 最後に必ず **Authorとして自身のモデル名を斜体で記載** する。
     - 例: `Author: *Gemini 3.8 Flash*`
4. **事実に基づいた正確な解析**:
   - 推測で記述せず、必ず対象ファイルの内容をツールで確認してから説明を作成する。

---

## ワークフローステップ

### 1. 対象ディレクトリと既存READMEの確認

1. ユーザーから指定された対象ディレクトリパスを確認する（未指定の場合はユーザーに確認する）。
2. ディレクトリ内のファイル一覧を確認する。
3. 同ディレクトリにある `README.md` を読み込み、現在の内容および `#### ソースコードの説明` 見出しの有無を確認する。

### 2. ソースコードの解析

1. 対象ディレクトリ配下の主要コード、スクリプト、設定ファイルを読み込む。
2. 以下の観点を整理する:
   - 各ファイルの役割・目的
   - 使用している主要ライブラリ・モジュール
   - 主要な関数・クラス・処理の流れ
   - モジュール間の依存・インポート関係

### 3. ソースコード説明文の生成

以下の構成で説明文を作成する:

```markdown
#### ソースコードの説明

このディレクトリは、〜〜〜（全体の概要を1〜2文）。

- `main_xxx.py`
  - 〜〜〜（具体的な処理内容）
  - 〜〜〜（使用ライブラリや連携）

- `modules/xxx.py`
  - 〜〜〜（モジュールの役割）

- `pyproject.toml`
  - 〜〜〜（主要な依存関係や前提バージョン）

（必要に応じて補足やまとめ）

Author: *<モデル名>*
```

### 4. README.md の更新

1. 生成した説明文を `README.md` の `#### ソースコードの説明` セクションに反映（置換または追記）する。
2. 他のセクション（記事URLやタイトル等）が維持されていることを確認する。

### 5. 完了報告

ユーザーに以下の内容を報告する:
- 更新した `README.md` のパス
- 追記した説明内容の概要
